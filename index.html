01 / 05Full-stack · Blockchain

ChainProof

Chain of custody for forensic evidence, where tampering shows up straight away.

Problem: Evidence passes through many hands between a crime scene and a courtroom, and every hand-off is a chance for someone to question it.

3independent records checked against each other: database, IPFS and blockchain

  • Next.js 14
  • TypeScript
  • PostgreSQL
  • Prisma
  • Redis
  • Solidity
  • Hardhat
  • snarkjs
  • Docker
How it works

ChainProof records each hand-off in three independent places, so a change to any of them stands out.

  • Each exhibit is hashed with SHA-256, pinned to IPFS, and registered on Polygon through a Solidity contract with OpenZeppelin role checks.
  • An integrity check compares the database, IPFS and the blockchain, scores any mismatch and alerts the admins.
  • Anyone can open the public verify page and confirm an exhibit's record without logging in.
  • Transfers carry a Groth16 zero-knowledge proof linking both officers. I haven't published the circuit files yet, so the demo labels those proofs as simulated.

02 / 05Backend · Infrastructure

Relay

A gateway that keeps LLM apps running when a model provider goes down.

257req/sat 3.4 ms p99 with zero failed requests, in a local k6 test against the mock provider

  • Go 1.26
  • Redis
  • PostgreSQL
  • Prometheus
  • Grafana
  • k6
How it works

Relay speaks the same API as OpenAI, so an app switches to it by changing one URL. Behind that URL it handles the parts nobody wants to write twice: API keys, rate limits, retries, failover and metrics.

  • Every provider has its own circuit breaker. Requests are routed by weight and retried with jittered backoff, so one slow backend can't drag down the rest.
  • Rate limiting is a token bucket inside a single Redis Lua script, so several gateway instances can't over-admit the same API key.
  • Retries stop once the first byte of a stream has gone out, so a client never receives the same response twice.
  • If Postgres or Redis is unreachable, only the features that need them switch off. The gateway keeps serving.

03 / 05Full-stack · ML

DevPulse

Reads your GitHub history and warns you before burnout does.

0–100experimental wellness score from commit timing, streaks and volume, with a 7-day forecast (trained on synthetic data)

  • React 18
  • Node.js
  • Socket.io
  • FastAPI
  • scikit-learn
How it works

DevPulse looks at the shape of your work: late nights, weekend commits, long streaks and sprint-then-crash cycles. It turns that into a score you can watch before the pattern becomes a problem.

  • Sign in with GitHub and a background worker imports your repos and commits, streaming progress live over Socket.io.
  • A separate Python service scores your wellness and forecasts the next seven days. The models are trained on synthetic data for now.
  • GitHub access tokens are encrypted at rest with AES-256-GCM and never appear in an API response.
  • Commit heatmaps, nine achievements, team leaderboards, PDF reports and a Monday-morning digest email.

04 / 05Frontend · Risk modelling

Nexora

Works out what fails first at a factory, before a flood finds out for real.

377golden-value tests across 16 engines. Change one formula and the build fails.

  • Next.js 14
  • TypeScript
  • Tailwind CSS
  • Radix UI
  • Recharts
How it works

Nexora models how floods, cyclones, toxic releases and grid outages would hit a specific facility: which assets fail, what each failure takes down with it, and whether the insurance would cover the loss.

  • A cascade engine walks each site's dependency graph and flags single points of failure.
  • Every number carries its sources, its assumptions and a confidence score, so it can be defended in front of an insurer or a board.
  • There's no backend. Sixteen pure calculation engines run in the browser, and the same input always gives the same answer.
  • The facilities in the demo are synthetic, and the app says so on every page.

05 / 05Full-stack · Databases

AutoLine

A car plant's production, parts and quality checks on one dashboard.

0queries rewritten to move from Oracle to SQLite. A translation layer handles the dialect.

  • React 19
  • Express 5
  • SQLite
  • Tailwind CSS
  • PDFKit
How it works

This was my Database Systems course project. It tracks what each production line is building, which parts are running low and what failed inspection.

  • Logging a production run deducts the parts it used from stock automatically, using the bill of materials.
  • I wrote it for Oracle first, then added a translation layer so the same SQL runs on SQLite and anyone can try it without installing Oracle.
  • Bulk stock updates and purchase orders are all-or-nothing transactions, with PDF bills generated on the server.
  • Admins, managers and operators each get their own view and permissions.
