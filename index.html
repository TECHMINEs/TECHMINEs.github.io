ChainProof

A tamper-evident record of who handled a piece of evidence, and when.

Evidence passes through a lot of hands between a crime scene and a courtroom, and every handoff is a chance for someone to ask whether it was altered. ChainProof records each handoff in three independent places, so changing one of them doesn't go unnoticed.

  • Every item is hashed with SHA-256, pinned to IPFS through Pinata, and registered on Polygon by a Solidity contract I wrote with OpenZeppelin role checks.
  • An officer accepts custody by signing with a passkey (WebAuthn) or an Ethereum wallet. The server checks the signature before anything is written on-chain.
  • A Groth16 zero-knowledge proof ties both officers to a transfer without putting their IDs on a public blockchain.
  • Anyone can open the public verify page and check the database, IPFS and chain records against each other, no login needed.

Code is private for now. Happy to walk through it on a call.

Relay

A gateway that sits in front of LLM providers and keeps apps running when one of them doesn't.

Relay speaks the same API as OpenAI, so an app can switch to it by changing one URL. Behind that it handles the unglamorous parts: API keys, rate limits, retries, failover and metrics.

  • Each provider gets its own circuit breaker. Requests are routed by weight and retried with jittered backoff, so one slow backend doesn't drag the rest down.
  • Rate limiting is a token bucket inside a Redis Lua script, which keeps it atomic even when several gateway instances share the same API key.
  • Supports streaming (SSE) and embeddings, exports Prometheus metrics, and ships with a Grafana dashboard.
  • In a local k6 test against the mock provider it handled about 257 requests a second with a p99 latency of 3.4 ms and no failed requests.

Code is private for now. Happy to walk through it on a call.

DevPulse

A GitHub dashboard that notices when you're heading for burnout.

I started this after a deadline where I was committing code at 3am for two weeks straight and didn't notice how bad it had got. DevPulse reads your commit history and points out patterns like that before they turn into a problem.

  • Sign in with GitHub and it syncs your repos and commits, with live progress updates over Socket.io.
  • A separate Python service (FastAPI + scikit-learn) gives you a wellness score from 0 to 100 and a seven-day forecast.
  • Commit heatmap, night-coding streaks, nine achievement badges, team leaderboards and a weekly email digest.

Nexora

Works out what breaks first at a factory, before a flood does it for real.

Small factories in India often don't know which part of their operation is the weak link until a flood or cyclone finds it. Nexora models a facility before disaster hits: what fails first, what that failure takes down with it, and whether the insurance would actually cover the damage.

  • Builds a dependency graph for each site and traces how one failure cascades, flagging single points of failure along the way.
  • Sixteen calculation engines cover hazard exposure, vulnerability, insurance gaps, accessibility and preparedness. They're all deterministic, so the same input always gives the same answer.
  • Worked examples include a flood-prone metal works in Howrah and a polymer plant near Visakhapatnam, plus a replay view for stepping through an incident.
  • There's no backend. Everything runs from data files, and a verification script checks every engine's output.

Code is private for now. Happy to walk through it on a call.

AutoLine

Running a car factory floor from one dashboard.

This started as my Database Systems project. It tracks what each production line is building, which parts are in stock, and what failed quality checks.

  • Logging a finished car deducts its parts automatically using the bill of materials, so stock levels stay accurate without anyone updating them by hand.
  • Fourteen screens covering production, parts, quality defects, employees, bulk orders and analytics, with role-based access.
  • Generates PDF bills on the server with PDFKit.
  • I wrote it for Oracle first, then added a SQLite mode so anyone can run it without installing Oracle.
